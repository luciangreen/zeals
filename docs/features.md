# Features, Commands, and Test Guide

ZEALS is a SWI-Prolog framework for exploring simplified algorithmic methods
("perturbations"), measuring their behavior, and synthesizing a guarded
fallback plan from the resulting evidence.

## Implemented features

### Problem and method declarations

Problems, cases, and perturbations are declared as Prolog terms and validated
when registered. Declarations support exact, one-of, predicate-based, unknown,
and unsupported expected outputs. Method contracts can specify a recognizer,
preconditions, executor, postconditions, failure modes, and verifier. See
[language.md](language.md) for declaration syntax and generation dimensions.

The registry provides deterministic identifiers and can be reset between
problem loads. The sample problems in `examples/` demonstrate maths,
classification, and sorting declarations.

### Generation and guarded execution

Perturbations can be generated by combining declared dimension values.
Compatibility, incompatibility, required-setting, and maximum-count rules
constrain the combinations. Generation is finite and deterministic.

Execution evaluates each registered method against each registered case. It
checks recognition and preconditions, applies a time limit, checks
postconditions, and runs problem-level and case-level verification when
enabled. Results include status, output, timing, confidence, diagnostics, and
an ordered trace. Unsupported inputs, timeouts, exceptions, and verification
failures are represented as explicit outcomes.

### Analysis and synthesis

The analysis stages provide:

- profiles with attempt counts, coverage, verified precision, failure rates,
  and average execution time;
- conservative capability hints inferred from shared successful features and
  observed failing features;
- failure boundaries derived from contrasting case outcomes;
- reusable-component extraction and dependency-graph utilities;
- a deterministic synthesis plan ranked using profile evidence, with an
  explicit unknown fallback when no verified method applies.

These are evidence-based heuristics, not formal proofs. See
[synthesis.md](synthesis.md) and [limitations.md](limitations.md).

The `zeals_explain` module provides explanation-dictionary helpers for
execution results, capabilities, and boundaries. Those helpers are not yet
integrated into `zeals_run/3`.

### Output, reports, interfaces

ZEALS can emit a loadable Prolog module containing problem and plan metadata
and a call into the ZEALS runtime. It can also write a Markdown report of
results, profiles, capabilities, boundaries, components, and the final plan.
The REPL exposes load, generation, execution, analysis, synthesis, emission,
report, and run commands.

## Commands you can run

Run all unit and integration tests from the repository root:

```bash
swipl -q -s test/run_tests.pl
```

The CLI test command runs the same suite:

```bash
swipl -q -s prolog/zeals_cli.pl -- test
```

Validate, synthesize, and report each included example:

```bash
swipl -q -s prolog/zeals_cli.pl -- validate examples/maths_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- synthesise examples/maths_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- report examples/maths_zeals.pl maths_report.md

swipl -q -s prolog/zeals_cli.pl -- validate examples/sorting_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- synthesise examples/sorting_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- report examples/sorting_zeals.pl sorting_report.md

swipl -q -s prolog/zeals_cli.pl -- validate examples/classification_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- synthesise examples/classification_zeals.pl
swipl -q -s prolog/zeals_cli.pl -- report examples/classification_zeals.pl classification_report.md
```

The CLI also supports `generate`, `execute`, `profile`, `boundaries`,
`components`, `emit`, and `run`. Its current commands select the first problem
declared in the input file. For example, emit a module or run an input term:

```bash
swipl -q -s prolog/zeals_cli.pl -- emit examples/maths_zeals.pl generated_maths_expert.pl
swipl -q -s prolog/zeals_cli.pl -- run examples/maths_zeals.pl 'equation(add(multiply(number(2),variable(x)),number(3)),number(7))'
```

Start the interactive interface with:

```bash
swipl -q -g "use_module(prolog/zeals_repl), zeals_repl:zeals" -t halt
```

At the `zeals>` prompt, enter Prolog terms such as `load('examples/maths_zeals.pl').`,
`problems.`, `synthesise(solve_equation).`, `show_plan(solve_equation).`, or
`quit.`.

## Test coverage

`test/run_tests.pl` runs these test modules:

| Test file | Coverage |
|---|---|
| `test_problem.pl` | Problem registration, validation, replacement |
| `test_generation.pl` | Dimension combinations, limits, compatibility |
| `test_execution.pl` | Correct, failed, and unsupported execution |
| `test_profile.pl` | Metrics and capability inference |
| `test_boundary.pl` | Failure-boundary detection |
| `test_components.pl` | Component extraction and dependency graphs |
| `test_synthesis.pl` | Plan construction and validation |
| `test_verification.pl` | Expected-output verification and candidate resolution |
| `test_emission.pl` | Generated-module loadability |
| `test_integration.pl` | Full maths workflow through emission and report |

The integration test writes generated artifacts to `test/generated_maths_expert.pl`
and `test/zeals_report.md`.

## Remaining implementation

The current synthesis stage constructs and validates a ranked plan, but
`zeals_run/3` does not interpret that plan: it matches the input against an
exact registered case and tries methods in registry order. Inputs without a
matching case return an explicit unknown result. Accordingly, emitted modules
delegate to the runtime and are not standalone expert implementations.

The next substantive feature work is to execute the synthesized plan as the
runtime dispatcher, select methods for inputs beyond exact registered cases
using verified capability/recognizer information, and return integrated
explanations and fallback traces. Multi-problem CLI selection and standalone
emission are also not implemented. Distributed execution, unrestricted
natural-language-to-code synthesis, GUI support, and machine-learning
integration remain out of scope for the first release.
